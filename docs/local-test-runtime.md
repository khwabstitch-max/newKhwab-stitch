# Local Windows MongoDB test prerequisite

The cached isolated MongoDB test binary requires Microsoft's Visual C++ runtime. It originally exited with Windows code3221225781 because the required runtime DLLs were unavailable. No application database, `.env` file, outside local folder or Ollama runtime was used to investigate this issue.

For this review, the official Microsoft Desktop Bridge runtime package was downloaded into ignored `artifacts/isolated-runtime` and its SHA-256 matched the [Microsoft winget manifest](https://raw.githubusercontent.com/microsoft/winget-pkgs/master/manifests/m/Microsoft/VCLibs/Desktop/14/14.0.33321.0/Microsoft.VCLibs.Desktop.14.installer.yaml). Only runtime DLLs were extracted into that same repository folder. A child-process-only PATH allowed the cached `mongod8.2.6 --version` to return0. No system package was installed, no global PATH changed and no files were copied from other local applications. Source/hash/probe evidence is in `artifacts/isolated-runtime/source.json`.

This is a local test-enablement measure, not a production runtime or a claim that Microsoft's Desktop Bridge package is the general installation method for every application. Microsoft's [runtime documentation](https://learn.microsoft.com/en-us/troubleshoot/developer/visualstudio/cpp/libraries/c-runtime-packages-desktop-bridge) describes that package's intended context. For an ordinary development machine, the supported operator-managed Visual C++ prerequisite or the Linux CI runner remains appropriate. Do not ship or commit the test DLLs/package. Review the applicable Microsoft package license before redistribution.

To reproduce from the repository root, run `node scripts/prepare-test-runtime.mjs`. The explicit Windows-only command downloads only the pinned official package when absent, verifies its published checksum, extracts an allowlist of DLLs inside the workspace and refuses different existing files. Repeating it reuses matching files. It performs a version probe if the cached MongoDB binary exists and writes safe provenance in `artifacts/isolated-runtime/preparation.json`.

The isolated test wrapper may prepend this folder only to its child environment on Windows after the local prerequisite is present. It must not change machine/user environment configuration. Disposable database files, browser profiles and temp files remain in this repository's ignored artifacts. Live MongoDB/ImageKit/email checks remain separate and were not enabled by this runtime probe.
