## Provider and deployment configuration

- Run the reviewed additive index migration after a backup. Production startup checks required retry/identity/action-token indexes without mutating them. Do not run development seed data against a customer database.
- Google is hidden until `GOOGLE_CLIENT_ID` is configured. Register the actual frontend origins and verify new sign-in, linking, cancellation and logout against the live provider. Historical Firebase IDs are retained but this is not a Firebase migration.
- Recovery/verification email requires `RESEND_API_KEY`, a verified `EMAIL_FROM` and exact trusted `PUBLIC_WEB_URL` together. Test actual delivery and expired links before announcing email recovery.
- ImageKit private originals, unsigned URLs, named transformations, signed expiry, quotas and deletion recovery still require live account verification. Private uploads remain fail-closed until the existing privacy configuration is explicitly verified.
- Keep the existing Render Static Site/Web Service deployment. Real orders require the operational checks in the deployment/operations guides, including non-sleeping compute, backups/restore, alerting and approved retention.

## Boundaries and remaining limitations

This is not a production-readiness assertion. No real Google account, outgoing email, courier, production backup/restore or hosted deployment has been verified by the isolated tests. The business must configure its actual design defaults/photos, rates/service areas, support calendar, approved policy versions and collaboration terms.

Replacement adjustments currently support explicit nonnegative surcharges; reductions are reviewed through the final quote. Accepted commercial snapshots cannot be edited in place: post-acceptance charge changes need a separately approved commercial amendment process, which is not automated. Draft proposals apply only to editable drafts, not submitted orders. No payments, worker payouts or real-time live-chat/callback service are introduced.

Cloud draft/message/application retention is deletion/operator-policy based; scheduled age-based purge and holiday-specific support calendars are not implemented. The request catalogue now supports server-filtered bilingual search and progressive batches of 12; per-component galleries and additions load bounded batches by garment/kind. Component search covers the loaded designs and is labelled accordingly. Selected designs, original defaults and measurements survive loading/filter changes.

Saved drafts, reviews/completed-order choices, notifications, applications, assigned jobs/assistance and the new admin review/service/application/worker/assignment screens now paginate. Assignment order/worker selectors load more choices without clearing the form. The completed-order review chooser does not guarantee exact cross-page eligibility filtering; the server still enforces one review per eligible owned order. Category/options and catalogue-default choices now load additional bounded batches; some legacy media reference pickers remain bounded to their first 50 records. Supplemental strings outside the localized gallery/wizard coverage still fall back to English when no Hindi translation exists. Language-state preservation remains covered by regression tests.
