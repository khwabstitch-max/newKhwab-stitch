# Boutique visual system

Khwab Stitch uses warm ivory (#FAF7F2), wine (#743F4B), plum ink (#35272C), a deep plum footer (#30232A), muted olive and champagne accents. The existing KS mark remains. Shared tokens live in `client/src/tokens.css`; semantic primary aliases also map older components onto this palette.

The body uses Manrope, headings use DM Serif Display, the wordmark keeps Cormorant Garamond, and Hindi uses Noto Sans Devanagari with local system fallbacks. The Google Fonts stylesheet is declared in `client/index.html`. No proprietary system font files are redistributed. Font-loading failures retain readable fallback fonts.

Presentation rules are separated by responsibility: `atelier-base.css` owns shared controls and surfaces, `atelier-home.css` owns the homepage, `atelier-shell.css` owns the header/footer, and `atelier-flow.css` owns request/account refinements. Existing application styles remain as compatibility foundations. The import order is explicit in `main.jsx`.

The homepage emphasizes on-demand custom stitching through a concise service headline, four visual frames (fabric, design, stitching, wear), photographic garment categories and catalogue previews, configured catalogue links and four operational process steps. The header keeps a Start stitching action visible on mobile; the footer uses deep plum, readable contact/help groups and a stitching invitation with clear actions. Images and labels distinguish illustrative stitching stories and design references from completed customer work. Owner-configured complete bilingual blocks and real published catalogue/review content remain supported. Exact previously shipped templates refresh for display without changing owner edits or API data.

Controls retain visible keyboard focus, accessible labels, error/disabled states and touch targets. Mobile navigation resets when returning to desktop. While the menu is open, background scrolling is locked and the main/footer are inert; Escape restores focus and closing restores the previous scroll setting. Account navigation collapses behind a labeled control. Request steps keep their active item visible, new steps focus their heading, and custom errors focus the error summary. Optional specifications and draft-privacy help remain available through native disclosures. Customer fabric, quote approval and required consent remain part of the workflow.

Each stitching-story frame has 300/600px WebP variants; the monogram is an optimized 144px WebP. Source assets are preserved. The current built-in image generation prompt, generated asset paths and verification commands are in [stitching redesign](stitching-redesign.md); [atelier redesign](atelier-redesign.md) records the earlier iteration.

Browser evidence uses the actual production bundle, installed Chrome and clearly labeled local read-only API fixtures. It does not certify every device, Safari, assistive technology, live customer data or deployed integrations. Retained older screenshots describe their historical build, not current verification.

The refreshed shell was verified in Chrome at 320, 390, 768, 1024, 1440 and 1920px in English/Hindi, with 44 page renders across home, catalogue, request, how-it-works, contact, login, password help and legal pages. The checks cover page bounds, readable footer contrast, 44px shell controls, menu focus loops, language/search/navigation, dropdown Escape/blur and desktop resize. Focused component checks and the production build passed.
